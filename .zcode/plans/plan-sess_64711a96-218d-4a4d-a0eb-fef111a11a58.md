Scan result (three read-only passes over API/chat hot paths, data layer/engine, and the live deployment): the codebase is in good shape after perf rounds 2–4; four small, low-risk fixes remain worth landing now. ## Changes

### 1. Hoist per-request regexp compile — `internal/api/dashboard_params.go:143`
`parseAnalyticsQuery` compiles `^(error|warning|info)$` on every analytics request. Add `var severityPattern = regexp.MustCompile(...)` to the existing package-var block (its four sibling patterns at dashboard_params.go:25–28 already do this) and pass it at the call site. No behavior change.

### 2. Kill the goroutine-per-request in the rate limiter — `internal/redisx/redisx.go`
`redisStore.run` spawns a goroutine + buffered channel + `context.WithTimeout` **per request** (twice for writes) solely because the shared go-redis client lacks `ContextTimeoutEnabled` (internal/api/middleware/ratelimit.go:451–477). In `redisx.Provide`, after `redis.ParseURL`, set `opts.ContextTimeoutEnabled = true` before `redis.NewClient` so go-redis honors context deadlines itself and the inline fast path runs. The goroutine fallback stays for other/custom clients. Regression test: assert the provided client's options carry `ContextTimeoutEnabled` (plus a scoped check that existing ratelimit tests still pass — they use their own clients).

### 3. Analyzer cheap guards — `core/analyzer/engine.go`
- `variableRefRegex` pass over every property value/variable per block: first verify the regex requires a `%` sentinel (read it; if it also matches another syntax, key the guard on whatever the regex mandates). Then add `if !strings.Contains(val, "%") { continue }` before the regex — allocation-free skip for the common no-variable case.
- `computeInsideRetryLoop` re-lowercases the LOOP parent's name and property keys once per child: memoize the "parent is a retry loop" verdict per parent block ID in one map, mirroring the existing `GroupHasHandler` memo pattern.

### 4. Singleflight around search-index builds — `internal/service/flow.go:806–822`
`searchIndexFor` on a cache miss builds the full index (tokenizes every block; ~23 MiB at 45k blocks) with no in-flight dedup — concurrent keystroke misses each rebuild and overwrite each other's cache entry. Wrap the build in a `singleflight.Group` keyed by `doc.ID`, following the existing pattern in `internal/service/chat_turn_memo.go`. Regression test: two concurrent `searchDoc` calls on a cold entry result in one build (count via the existing cache/index seams if a hook exists; otherwise assert single shared result + one cache entry and keep it proportionate).
