# API architecture: co-location + file splits (low-risk set)

## Goal

Adding or changing an endpoint should touch one file. Today routes live centrally in `routes_chi.go` (227 routes) while handlers sit in six 750–1,300-line files spanning multiple sub-resources. All changes are same-package code motion — compile + the 103-file test suite protect every step.

## 1. Split the six giant handler files along sub-resource seams

Agents (disjoint ownership, 2 concurrent) move whole functions + their doc comments **verbatim** between files in `package api`; no logic changes; new files get the right package clause + imports; compile+test after each file.

| Current file | New files |
|---|---|
| `handlers_org.go` (1,263) + OrgHandler methods currently inside `handlers_azure_registry.go` | `org.go` (struct, helpers, CRUD, route composition), `org_members.go` (members+invites), `org_azure.go` (all Org Azure methods from both files), `org_knowledge.go`, `org_channels.go` |
| `handlers_flow.go` (1,083) | `flow.go` (struct, upload/load/recent/search), `flow_source.go` (source/snapshots/suppress/tags), `flow_blocks.go` (8 block ops), `flow_fixes.go` (apply/preview/batch) |
| `handlers_auth.go` (1,095) | `auth.go` (struct, register/login/refresh/me/logout, SSO already separate), `auth_password.go` (change/forgot/reset/verify/resend), `auth_account.go` (sessions, revoke, GDPR export/erasure) |
| `handlers_analysis.go` (911) | `analysis.go` (struct, analyze/raw/batch, exports), `analysis_findings.go` (lineage/graph/dataflow/deps/diff/history/dedupe/related/compare), `analysis_rules.go` (rules, custom rules, config) |
| `handlers_azure_registry.go` (819) — ProviderHandler half | `providers_azure.go` (connections+models CRUD, discover, test) |
| `handlers_library.go` (764) | `library.go` (struct, CRUD, content), `library_versions.go`, `library_portfolio.go` |

Ownership note: OrgHandler Azure methods span two files today; the org agent owns both sides of that move (the azure_registry agent touches only ProviderHandler methods).

## 2. Co-locate route registration (done by me after the splits, single-owner)

- Each sub-file that owns a URL group gets a `registerXRoutes(r chi.Router)` method containing its route block **moved verbatim** from `routes_chi.go` (preserving chi nesting/middleware exactly): `org_members.go` registers `/members` + `/invites`, `flow_blocks.go` registers `/block/*`, `providers_azure.go` registers `/azure-foundry`, etc.
- Area top files get a small composition method (`registerRoutes` calling sub-registrations) — stable, rarely touched.
- `routes_chi.go` shrinks to: public routes (`/api/events`, `/api/shared`, `/api/integrations/ci`), one register call per area, static/NotFound handling (~60 lines).

## 3. Break the `serveSharedShell` reach-through

`router.go` reaches into `rt.handlers.Analysis`'s unexported `backend`/`flowSvc`. Add one exported method on `AnalysisHandler` (e.g. `LookupSharedFlowHeader(ctx, token) (*interfaces.FlowDocument, error)`) encapsulating the nil-checks + `GetShareTokenByHash` + `LoadFlowHeader`; the router calls it. (This also prepares any future package split.)

## 4. Dashboard ownership — no change (corrected)

Inventory shows `DashboardHandler` is a genuine BFF for `/api/dashboard/*` and `/api/analysis/dashboard` is a different analysis-scoped report; both are correctly owned. Nothing to do.

**Swagger:** left as-is — mass-adding annotations is mechanical but untestable without regenerating `docs/docs.go`, so it's not in the low-risk set.

## Verification

After each split: `go build ./... && go vet ./internal/api/ && go test -count=1 ./internal/api/...`. Final: full root suite (`-p 4`), core suite untouched, golangci-lint (must stay at the 6 pre-existing hits), CRLF check on all touched files. Route behavior is pinned by existing tests (`route_path_test.go`, `security_integration_test.go`, per-handler suites). No git commands; no Docker rebuild needed (production behavior unchanged, but if the user wants, rebuild+redeploy at the end anyway for cleanliness).
