## Phase 3 — RAG quality: chunking, batching, retrieval assembly (2026-08-22)

The knowledge-base pipeline (org guideline docs → chunks → embeddings → per-turn retrieval into chat context) had one indexing-failure bug, one silent invariant violation, and three retrieval-quality gaps.

- [x] **RAG-1 Chunk-size invariant actually holds now.** `splitSentences` only hard-split a paragraph when it had ≤1 sentence terminator; a paragraph like "Intro. <5000-rune run with no period>" returned the oversized run whole and `chunkText` appended it verbatim — a 5000-rune chunk where the contract says ≤1000 (embedding providers bill per token and cap per-item length, so the whole indexing request could fail or distort). Oversized pieces are now hard-split on rune boundaries in every case; the paragraph/sentence fit-guards became loops so a carried overlap that still doesn't leave room is dropped instead of overflowing (carry 15 + unit 100 + delimiter 2 used to emit 117-rune chunks). The old test tolerance (`size + overlap + 1`) was masking this — tightened to strict `≤ size`.
- [x] **RAG-2 No pure-overlap noise chunks.** A trailing/mid-stream "chunk" containing only the carried overlap tail duplicated the previous chunk's ending verbatim — guaranteed retrieval noise (two vectors over the same passage, double context tokens when both hit top-k). `flush` now refuses to emit carry-only content (`hasNewContent` tracking) and drops the carry when the next unit needs the space.
- [x] **RAG-3 Provider-safe embedding batches.** `AddDocument` sent ALL chunks (up to 500) in ONE `/embeddings` request; providers cap input items per request (OpenAI/Azure ~100), so a 101+-chunk document failed indexing wholesale after chunking had already succeeded. `embedBatched` (100/call, results concatenated in order, per-batch count checked) makes large documents index successfully on every provider.
- [x] **RAG-4 Source attribution.** Retrieval results carried no filename — the model couldn't cite which document a guideline came from, and users got guidelines asserted with no provenance. `KnowledgeChunk.Filename` is joined at query time (`d.filename`, both the pgvector pushdown and the Go-side fallback — no migration; rank pass-through preserves it), and assembly renders `- [naming.md] …` bullets.
- [x] **RAG-5 Overlap de-duplication at assembly.** With 15% chunk overlap, top-5 frequently returns adjacent chunks where N+1 begins with the exact tail of N — the same passage paid for twice in context tokens. `stripOverlapPrefix` (exact-string match, same-`DocID` scoping, ≥60-rune coincidence floor, longest match first) trims the carry; a chunk fully contained in its neighbour is skipped. Cross-document identical tails are deliberately NOT trimmed (same bytes ≠ same source).
- [x] **RAG-6 Grounding instruction.** The header was a bare "**Relevant Organizational Guidelines:**" label; the assembled block now instructs: apply where relevant, cite the source file when relied on — advisory (the flow's actual code wins), not an override.

+tests: `TestChunkText_SizeInvariantAllInputs` (terminator-free, mixed-terminator, oversized-between-normal shapes), `TestChunkText_NoPureOverlapTailChunk`, `TestEmbedBatched_ProviderSafeBatches` (batch shape 100/100/100/50 + order + error + count-mismatch), `TestAssembleGuidelines` (header/attribution/dedup/cross-doc no-trim/below-floor no-trim/full-duplicate skip), tightened `TestChunkText_SplitsByRunesNotBytes`.

## Phase 6 — Security & agentic-core correctness (2026-08-22)

Round-2 deep dive (five parallel audits: tool loop, context/prompts, RAG lifecycle, providers/streaming, frontend UX) surfaced 20+ findings; this phase closes the security and correctness core. Two invariant threads run through it: **everything the model or client sees is scrubbed** (real secrets never leave the server), and **the model's tools always describe the flow as it actually is** (real-doc analysis, fresh post-fix documents).

- [x] **S1 Source files AST-scrubbed (`ScrubSourceText`).** Selected source files were injected as raw disk bytes; PAD's `SET Password TO $'''secret'''` / `Text: $'''secret'''` syntax matches no `key=value` regex, so the trailing `ScrubText` pass masked nothing — the AST-level property-name masking the document path gets was fully bypassed. New `scrubber.ScrubSourceText` parses the file and replaces every sensitive property VALUE at its literal occurrences (same rules as `ScrubDocument`: action-specific fields, credential-named keys, SET-TO targets; pure `%Var%` refs and <3-rune values skipped), then runs the regex pass; parse failures fall back to regex-only. Companion fixes: `scrubBlock` now masks `_value` when `_var` names a credential (the SET gap existed in the DOCUMENT path too — synthetic keys hid it from the field-name pass), and `sensitiveActions` gained the fill-action family (`FillTextByText/Name/Placeholder.FillWith` — `FillWith` is the value typed; `Text` stays visible as the locator). Service wiring in `computeContextCore`; scrubbed content rides the existing context cache.
- [x] **S2 Chat RAG gated on org membership.** A flow collaborator without org membership (flows policy allows it) got the org's KB guidelines injected — content the knowledge REST API refuses them (`requireMember`); the chat path is RLS-exempt so nothing else stopped it. `ragGuidelines` now requires `isOrgMember` (narrow local interface over the org store, not a `chatStore` widening): fail-closed on store errors, empty identity, nil backend. Local mode unaffected (no orgs ⇒ no org-owned flows).
- [x] **A2 Fix tools analyze the REAL doc; outputs stay scrubbed.** `list_findings`/`resolveFixTarget` analyzed the scrubbed copy, so value-dependent findings (hardcoded credentials: `[REDACTED]` matches no credential pattern) vanished — `apply_fix` failed with "no finding" for exactly the security findings the UI lists, and scrubbed fingerprints degraded verification. `ToolContext.RealDoc` (server-side only) now feeds analysis + fix resolution; finding BLOCK still comes from the scrubbed doc so patch previews render masked values by construction; finding titles scrubbed before leaving the server. - [x] **A1 Post-fix document refresh (multi-fix streams work).** `tctx` was bound once at stream start; the apply re-parse mints NEW block IDs, so a second fix in one stream always failed "block not found" and follow-up tools described the pre-fix flow. - [x] **A3 Copilot prompt-loop wire format fixed.** Tool results fed back as a bare `role:"tool"` message — schema-invalid on OpenAI-compatible wires (tool messages must answer an assistant `tool_calls` turn this protocol never emits), so Copilot 400-rejected the second request of EVERY tool conversation. Results now return as a user message with `<tool_result name="…">` markers, and the protocol instructions document the format. Plus the first service-level `runPromptToolLoop` test (the gap is why this survived).
- [x] **Prompt-loop truncation pins the user's question.** Tool instructions were injected as a leading system message; `truncateForContextWindow` pins `Messages[:1]`, so under overflow the junction repair dropped the USER'S TURN (context + question) while tool-instruction boilerplate stayed pinned.
