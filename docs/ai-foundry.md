# Azure AI Foundry accounts

How AI accounts are configured in-app (**Settings → AI Accounts**, `Ctrl + ,`) and the Azure AI Foundry resource/model registry. Backend provider machinery: [architecture/ai-providers.md](architecture/ai-providers.md).

## Resources, credentials and models

- Azure public cloud only (no Government/China); Entra sign-in pinned to `login.microsoftonline.com`. Up to **10 resources**, each with its own endpoint (`https://<resource>.openai.azure.com`, `.services.ai.azure.com` or `.cognitiveservices.azure.com`; serverless `*.models.ai.azure.com` is refused — deploy the model to a Foundry resource) and credentials: API key, Entra service principal (tenant GUID or domain, never `common`/`organizations`; the app registration needs **Foundry User** on the resource) or desktop-only Azure CLI. Up to **50 models** (deployments or agents), each with a purpose.
- Each chat thread keeps its own model; new chats start on Default for new chats, else the imported default, else the organisation's default. Azure deployments cannot be listed with an API key — add them by name; Entra ID + a project endpoint suggests the project's deployments and agents (**Foundry User**; **Foundry Agent Consumer** can run an agent but not list them).
- Agents (project endpoint + Entra) run through the Responses API, stateless (`store:false`; one answer's tool-loop items are replayed encrypted with its next request). The app executes an agent's function tools named like its flow tools (`search_flow`, `get_block`, `get_subflow_blocks`, `list_findings`, `propose_fix`, `apply_fix`, `apply_fixes`, `get_variable_lineage`). MCP tools must set `require_approval: "never"` (the app cannot answer approvals). Workflow agents retire 2026-12-01 (`Foundry-Features: WorkflowAgents=V1Preview` opt-in). The per-thread Tools toggle does not apply to agents.

## Limits and policies

- Reasoning models (o-series, GPT-5 and GPT-6 families, gpt-oss, DeepSeek-R1 / MAI-DS-R1 / V3.2-Speciale / V4-Pro, MAI-Thinking-1, Grok 4 / grok-code-fast-1, Phi-4-reasoning, Claude 5.x and Fable/Mythos, unknown `claude:` deployments, model-router deployments) are sent at least **16384** max output tokens regardless of Max Tokens (still capped at the model's own limit); a turn that spends it all before answering fails `PROVIDER_OUTPUT_LIMIT`. Temperature 0 is honoured as 0.
- Knowledge base: embeds only with `PAD_EMBEDDING_PROVIDER=azure-foundry` and one model per user/org marked **Use for knowledge base** (an org with Azure resources but none marked does not fall back to a member's). Changing or removing the marked model on a non-empty corpus answers `409 REINDEX_REQUIRED` until confirmed; uploads with a different embedding model are refused `EMBEDDING_MODEL_CHANGED`. Embeddings use `PAD_EMBEDDING_DIM` (default 1536, never above the model's native width).
- Azure usage is not priced or budget-gated by baki (cost is in the Azure portal, hosted tools included); the daily AI budget never refuses an Azure turn or Azure-embedded upload, while priced-provider embeds on a spent org budget are refused `429 BUDGET_EXCEEDED`.
- Endpoint allow-lists: `PAD_AZURE_FOUNDRY_ALLOWED_HOSTS` (exact hosts or `*.suffix` globs; a glob over a public suffix or multi-tenant zone such as `*.azure-api.net` refuses boot) and `PAD_AI_ALLOW_PRIVATE_EGRESS=true` for private-link addresses (loopback, link-local and other internal ranges stay refused).
- Claude on Foundry needs a pay-as-you-go Azure Marketplace subscription and is added as a model of kind **Claude** (called via `/anthropic/v1/messages`, streaming and tools); Claude calls always go to `<resource>.services.ai.azure.com` even when the endpoint is `.openai.azure.com`. Context: 1M for Opus/Sonnet 4.6+ and the 5.x models, 200k Sonnet 4.5 / Haiku 4.5; the Mythos tier is Entra-only (no API key).

## Sharing and the model registry (schema v25)

- Shared organisation resources (web, Settings → Organizations) are visible and runnable by admins and members only. Secrets are write-only (members see endpoint, auth mode, tenant/client IDs, models, lender, timestamps); the lending admin's demotion, removal or account deletion disables their credentials (resources stay listed, needing new ones). Saves are compare-and-swap on `updatedAt` → `409 CONFLICT`; an omitted secret keeps the stored one only while the host is unchanged. Usage is attributed to the organisation and not budget-gated.
- Registry routes: `/api/providers/azure-foundry/connections[/{id}[/discover]]`, `…/models[/{id}]`, `POST …/test` (the same under `/api/orgs/{id}/providers/azure-foundry/`); chat names a model by its `m/<id>` from `GET /api/providers/list`; an unusable model is refused `400 MODEL_NOT_AVAILABLE`.
- **Rolling back to a pre-v25 image:** stop the app (`docker compose stop app` — a running new image would re-apply v25), run `go run ./cmd/bakicli migrate down --dsn "<DSN>" 24` from this checkout, then deploy the older image (older images refuse a newer schema). This deletes the model list and every resource but the imported one.
