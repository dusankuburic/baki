# Test map

Tests live in the same directory (and package) as the code they test; file names encode the coverage area: `<area>_<subject>_test.go`. This is the per-package browse-by-coverage map; each package's doc comment states what its files pin.

Conventions: `*_test.go` in-package files may use unexported identifiers (white-box); `internal/storage/database` also has `package database_test` black-box integration files; `helpers_test.go` / `main_test.go` are shared helpers, not coverage files. Run everything: `go test ./... ./core/...` (CI adds `-race`). Cross-cutting safety nets (route-policy and authz goldens, migration checksum golden, findings/export/caches goldens, architecture ratchets, fake-backend contract, isolated Postgres databases, request-chain benchmark): [architecture/safety-nets.md](architecture/safety-nets.md).

The egress net (ADR 0034): `chat_egress_test.go` plants one unique canary secret per channel in a fixture flow (an unknown-action property, a URL with userinfo and `sig`, an IF literal, a comment token, a hardcoded-url finding, a selected source file, the question, a history message, RAG guidelines, every read tool's result, the fix preview, provider error text) and runs a plain stream, the tool loop and the prompt loop against the capturing fake provider; no canary may appear in any captured `ai.Request` or emitted SSE event. `testutil.FakeProvider{RequireScrubbed: t}` makes any chat test fail when an outgoing request holds a string `ScrubText` would change, and `chat_scrub_failclosed_test.go` proves the two scrub fallbacks fail closed (a failing `scrubDocument` never lets the document itself reach the context or the tools). Add a channel to the canary list when you add one to the product.
