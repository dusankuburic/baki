## Rules for new code

- **Layers.** `internal/api` reaches storage through services and the `storage/interfaces` role interfaces, never the Postgres package; `internal/service` never imports `internal/api`; `core` is a separate module out of `internal`'s reach (`internal/archtest`).
- **Transactions.** Writes go through `withTx` (joins the request's RLS transaction), `withTxAs` (own transaction as the user) or `withOwnTx` (never joins, for writes that must outlive the request's rollback); a raw `BeginTx` beside them runs without RLS ([transactions.md](transactions.md)).
- **Account writes.** A live account changes through the targeted `UserStore` updates, one statement per operation writing only its own columns; `SaveUser` (whole row) stays in seeding and tests (`TestArch_SaveUserOnlyInStorageAndTests`).
- **Tenant scoping.** Row-level security limits a table to the caller's rows, roles via `AuthzService.Can`; a new table gets a policy or a reason in `TestRLS_TablesWithoutRowSecurityAreListed`, and cross-tenant reads stay in the jobs `TestArch_SystemReadsPinned` lists (ADR 0013).
- **Endpoints.** New endpoints put their logic in a service (authorization, audit, cache invalidation) and are built with `api.JSON`/`api.Query` from a typed request to a typed response: `Validate`, `FlowRef` + `AuthorizeFlow`, `PageRequest` into `Page[T]`, errors as `apperr.Error` via `render.Error` ([api-conventions.md](api-conventions.md)); the hand-written-route count per file only goes down.
- **Post-commit work and responses.** What must happen only once a write is durable (blob purges, emails, cache invalidation) goes through `txhook.Register` — after the commit, dropped on rollback, own RLS scope; the transaction commits before the first response byte, and once a handler writes it must not touch the database again (ADR 0004).
- **Wiring.** Dependencies in constructors; a post-construction `Set*`/`On*` in `internal/di` only for a cycle or a listed deferral, every one pinned with its reason (`TestDISetters_Listed`, [di-wiring.md](di-wiring.md)); when two services need each other, extract the part both need.
- **Events.** A change another module derives from is a domain event (`internal/events`, ADR 0009) published by the service that made it, inside its transaction; cache invalidation is a sync subscriber with generation-checked fills (`eventbus.Gen`), side effects are async subscribers run only after the commit; every subscriber declares `eventbus.Local(reason)` or `eventbus.Replicated(invalidation keys)` — no default, all listed in `subscribers.golden` ([safety-nets.md](safety-nets.md#event-subscribers-internalditestdatasubscribersgolden)); never call another service to announce a change or add a hook setter for it.
- **Server-sent events.** `api.EventManager` delivers locally and, with the shared Redis, to other replicas through `api.EventFanout` (`redisx.SSEBackplane`, ADR 0030): deliver locally, publish once; durable events get an `id:` from a per-user Redis Stream and `Last-Event-ID` replays from it; `HasSubscriber` answers true when it cannot read presence.
- **Caches.** Declare once with `cache.Declare(name, cache.Keys(...), ...)`: a tenant key part unless `cache.Global(reason)`, and a locality (`cache.ReplicaLocal(reason)` or `cache.Shared(cache.MechanismInvalidation, ...)`); fill via `cache.New`/`GetOrFill`; any other per-process keyed state goes in `stateRegistry` (`TestArch_PerProcessStateDeclared`, ADR 0032); declarations are in `caches.golden` (ADR 0017).
- **Background work.** Anything that must not hold up the request runs on a `lifecycle.NewBounded` runner (capped, reports panics, drained at shutdown), never a bare `go func`.
- **Metrics and logs.** A package registers its own metrics with `metrics.MustRegister` from a package-level var/init (`internal/metrics/testdata/metrics.golden`, refresh `-update-metrics`; the central list only shrinks); log on the request path through `logger.FromContext(ctx)` so lines carry `request_id`/`user_id`/`trace_id` from `middleware.RequestInfo`, plus what `logger.WithAttrs` added to the context (a chat turn's `stream_id`); the chat and AI code's bare `logger.*` calls are pinned by `TestArch_BareChatLogCallsRatchet` and only go down.
- **Audit.** Record through an injected `*audit.Recorder` (`Record(ctx, audit.Entry{…, OrgID})`; the actor from the context — a background job sets `auth.SystemActor(name)` — address and user agent from `reqinfo`); `internal/audit` never imports `internal/api` (ADR 0008).
- **Data lifecycle.** Every table is claimed in a `lifecycle_<domain>.go` file of `internal/storage/database`: what export, erasure, organisation deletion and the retention sweep do with it (`TestPostgres_Lifecycle_EveryTableClaimed`, ADR 0011, [data-lifecycle.md](data-lifecycle.md)).
- **Secrets.** Credentials stored outside the keystore are sealed with `sealField`/`openField` and listed in `fieldSealedColumns` for the rotation re-seal pass (ADR 0005); values that carry a credential travel as `secret.Value` — `[redacted]` everywhere, plain text only through `Reveal()` at the boundary, compared with `Equal`. A secret store failure reaches the client through `render.Error` as 503 `SECRET_STORAGE_UNAVAILABLE` or 422 `KEY_UNREADABLE` (`service.SecretStoreError`), and a credential's state is read, not checked for a row: `configured`, `unreadable` or `missing` (ADR 0040).
- **Configuration.** Environment variables are read only in `internal/config`; `config.Load` builds the configuration once (durations parsed, ranges validated) and providers share the one `*config.Config` and never write to it (`TestArch_ConfigNotMutatedOutsideConfig`).
- **Deployment modes.** Ask `capability.Of(cfg)` what the process can do; don't compare `cfg.Mode` or test for a nil backend.
- **AI providers.** A provider is described once, as an `ai.ProviderSpec` in `internal/ai/spec_<id>.go`; every provider list derives from `ai.Specs()` (`internal/ai/testdata/providers.golden`, refresh `-update-provider-specs`); never branch on a provider id by name — ask the spec (`Caps`, `Keys`, `Modes`, `Listing`) (ADR 0025, [ai-providers.md](ai-providers.md)). A provider's HTTP call goes through `doProviderRequest` (a transport timeout is `ErrProviderDown`), and a non-200 answer is classified status first into the shared sentinels retry and the breaker act on (ADR 0041).
- **Chat tools.** A tool is an `ai.ToolSpec` in `internal/ai/tools.go` (`internal/ai/testdata/tools.golden` pins its flags, description and schema, refresh `-update-tools`); the stream's `ai.ToolGate` (actor scopes, approvals wired, flow edit permission) decides what is offered and is asked again in `ExecuteTool` — ask `ai.ToolRequiresApproval`, never test a name; a tool that must ask the user goes through `ChatService.requestApproval` and bounds its own apply window; the system prompt follows `ai.ToolAccess` (`internal/ai/testdata/prompts.golden`, refresh `-update-prompts`) (ADR 0026, ADR 0038). An approved fix finds its finding again by the proposal's anchor, runs as a critical section a stop waits for, reports failures in curated words and leaves audit rows; no approval is asked or approved while the server drains; the chat event envelopes are pinned in `internal/service/testdata/chat_events/` (`-update-chat-events`), which the frontend parser's contract test reads (ADR 0039).
- **Chat conversations.** In cloud mode a stored conversation has a `version` (migration 0044) and the server's own writers go through `ChatService.mutateConversation` (read, change, `SaveConversationIf`, re-read on conflict); a client save may carry `baseVersion` (409 `CONVERSATION_CONFLICT` without it); local modes keep files and have no versions (ADR 0031).
- **Chat stream commands.** A stream lives on the replica that started it: a stop or approval landing elsewhere goes through `ChatService.CancelStreamAs`/`DecideApproval` on the owner's `baki:chat:cmd:<instance>` channel; with Redis unreachable the answer is 503 `REPLICA_UNREACHABLE`, never an ok; never read `activeStreams` for a stream another replica may own (ADR 0033).
- **Egress scrub rule.** Every string the model can see passes the scrubber before the provider boundary, and nothing fails open: `ScrubDocument`/`ScrubSourceText` for a flow and its source, `ScrubFreeText` for a message, a query or an upload, `ScrubText` for the rest; `internal/service/chat_egress_test.go` is the net under every channel and `testutil.FakeProvider{RequireScrubbed: t}` fails a test that sends an unscrubbed string (ADR 0034).
- **The turn's request.** The stream and `PreviewContext` build a turn's `ai.Request` through one `ChatService.assembleTurnRequest` (context, history, frames, parameters, the gate's tools or the marker instructions); `BuildContext` is deterministic, and a change to the prompt shows up in `internal/service/testdata/request_snapshots/` (refresh `-update-request-snapshots`, review the diff) (ADR 0035).
- **Data frames.** Flow-derived text and the organisation's documents reach the model inside `<flow_context>`, `<org_guidelines>` and `<tool_result>` frames (`ai.Frame`, `ai.ToolResultFrame`, content escaped so nothing inside can close a frame) and the system prompt says what is inside is data, not instructions; never put such text in the turn outside a frame (ADR 0036).
- **No budgets or prices.** Baki records AI usage as token counts only; there is no spend cap, no model price and no cost field anywhere (ADR 0037). Spend is read in the vendors' consoles and the Azure portal.
- **Storage capabilities.** Never type-assert a store to learn what it can do (ADR 0010): a method any store could offer joins its role interface; what only the database offers (cross-replica lock, request transaction, keystore, …) is an fx value `internal/app` provides beside the backend, nil without a database.
- **Migrations and settings.** New steps are `.sql` files with a `-- baki:compat expand|breaking` line (prefer expand/contract; never edit a shipped step — checksums pinned); each top-level `AppSettings` key is a versioned section (`internal/storage/settingsdoc/sections.go`), a stored-shape change raises its version with an upgrade, and a field never changes its JSON type (ADR 0012). A settings write is checked against the caps in `internal/service/settings_validation.go`, which `frontend/src/lib/constraints.ts` mirrors (a test compares them), and the client posts only the sections it changed (ADR 0040).
- **Routes.** A feature mounts its own routes (`api.Module.Mount(rb)`, the fx `routes` group) and declares each route's policy where it registers — caller, token scopes, rate-limit bucket, RLS transaction, deadline class, capabilities; no central route list, no middleware path tables, a route without a policy does not boot; a route that creates a record declares `route.Idempotent()` (ADR 0006/0007); a route whose handler can reach a billed provider call (`ai.Provider` Chat, Stream or Embed) declares `route.Billed()` and rides a cost bucket (chat or embed): the router refuses it on any other, and `TestBilledRoutes_MatchTheCallGraph` derives the billed set from the call graph ([operations.md](operations.md#rate-limits)); review `route_policy_declared.golden` (legacy tables decide until `PAD_ROUTE_POLICY=declarative`).
- **Old clients.** A new enum value ships one release after the frontend's tolerant parsing that accepts it (only roles and `Finding.severity` stay closed); a 404 provider catalogue falls back to the frontend's built-in sections; every response carries `X-Baki-Version` so a stale tab offers one reload per server build.
