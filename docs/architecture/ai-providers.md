# AI providers: the spec registry

A provider is described once, as an `ai.ProviderSpec` in `internal/ai/spec_<id>.go`, registered at init (ADR 0025). Every provider list is derived from `ai.Specs()` — the factory, the keystore keys, the embedding order, the listing, the catalogue route, the pricing fallback — and `internal/ai/testdata/providers.golden` pins the table: refresh with `go test ./internal/ai/ -run TestProviderSpecs_Golden -update-provider-specs` and review the diff. Never branch on a provider id by name: ask the spec (`Caps`, `Keys`, `Modes`, `Pricing`, `Listing`); `TestArch_ProviderIDLiteralsOutsideSpecs` pins the literal count per file (only downward), and `TestArch_RegisterProviderOnlyInTests` keeps `RegisterProvider` out of production code.

Load-bearing spec fields: `Caps` (`chat`, `stream`, `embeddings` — with `EmbeddingIdentifier`, `tools`, `reasoning`, `model_aliases`, `live_listing`, `org_shared`, `prompt_cache`); `Modes` (the capability profiles the provider is offered in); `Egress` (`fixed_host`, `user_endpoint` — allow-listed and dial-guarded in the cloud profile — or `loopback`, never in the cloud profile); `Credential` (kind `api_key`/`oauth_device`/`document`/`none`, with typed `Fields` and `HelpURL`); `Keys` (the keystore rows: `Primary`, `OAuthToken`, `Family` for Azure resources); `Pricing` (`catalog` — the default model's row as fallback — `free`, `unpriced`); `Wire` (`anthropic`, `openai`, `gemini`, `responses`); `Resolver` (reads the credential when the rule is not "Keys.Primary"); `Ctor` (builds the raw provider); `Listing` (a `ListingHook` for a family whose state and models live outside the keystore — the Azure AI Foundry registry, installed from DI with `ai.InstallListing`). Copies that cannot import `ai` are pinned to the registry: `internal/config.EmbeddingProviderIDs` (`TestEmbeddingProviderIDs_MatchRegistry`), `core/models.DefaultSettings().AI.Providers`, the frontend's known set (the tolerant client renders unknown ids from the wire).

On the wire, `GET /api/providers/list` entries carry optional `caps[]`, `modes[]`, `credential{kind,fields[],helpUrl?}`, `pricing`, `color`, `icon`, `configurable`, and `GET /api/providers/catalog` (same policy) answers every registered provider of the running profile, configured or not, with its credential schema and per-kind `endpoints`. An id no spec describes is `PROVIDER_UNKNOWN` (400 on `/api/keys/*`, chat create and the context preview; 200 `{ok:false}` on `/api/providers/test`; the stream error code) — the codes are in [api-conventions.md](api-conventions.md).

## Adding a provider

1. A catalogue entry in `internal/ai/catalog.go` and a `spec_<id>.go` registering at init: `Caps` as the provider truly behaves (`TestProviderSpecs_Complete`), `Modes`, `Egress`, `Credential`, `Keys{Primary: id}`, `Pricing`, `Wire`, `Ctor`, a unique `Order`.
2. A `Ctor` over an existing wire family (`openaiBase` for an OpenAI-compatible vendor) or a new provider file — which never spells its own id literal (the ratchet fails on it).
3. Refresh `providers.golden`; add a `core/models.DefaultSettings` row (a pin requires one); an embedding-capable provider also joins `internal/config.EmbeddingProviderIDs`.
4. A device-flow provider needs its auth routes; a family with its own registry adds a `ListingHook` installed from DI. A bare-key provider needs nothing else.

## The in-flight budget ledger across replicas (addendum to ADR 0028, Phase 5b)

- **Which ledger.** `PAD_MAX_REPLICAS > 1` with `PAD_REDIS_URL`: `redisLedger` (`internal/service/ai_budget_redis.go`). Anything else — including a single replica with `PAD_REDIS_URL` set — keeps `memLedger`: the Redis ledger fails closed, and a replica with nothing to share must not lose chat to a Redis blip (`provideAIBudget`). `hold` failing refuses the stream with `ErrAIBudgetUnavailable` before a worker is counted; `release` failing is logged and left to age out.
- **Keys.** `baki:ai:inflight:user:<scope>` and `baki:ai:inflight:org:<orgID>`, hashes with one field per running stream (a random handle, never the user or the client's stream id), value `{v, kind, cost, exp}`; the holder rewrites its field every second, so overlapping checks see each other. Readers skip their own field, fields past `exp` (a 30 s lease — a dead replica stops counting after it) and fields that do not decode (never deleted: another release may have written them). Hash TTL 11 minutes; both keys are declared in the registry with `on-down: closed`.
- **The bound.** A stream is admitted while the others' in-flight spend is under the budget, so reservations total less than the budget plus one reservation whichever replicas start them; between refreshes a stream's cost grows at most what its reservation covers. A start stampede can refuse all of its members — a retry, not budget.
- **Redis down.** Only while a daily budget is configured (`AI.DailyBudget > 0`; with none nothing touches Redis). With one, every entry point refuses `AI_BUDGET_UNAVAILABLE` — a new turn, the start check, every tool-loop re-check, the audited wrapper's per-call hook — and a running stream stops at its next re-check ("couldn't verify today's AI budget"). No grace period, no last-known-sum cache: unreadable means refuse, the rule ADR 0028 pins. Recovery is automatic.
- **Eviction.** A held stream rewrites its record every second; a rewrite that had to recreate a record another writer lost fails the next budget check closed once (`pad_ai_ledger_errors_total{op="lost"}`) and the record is whole again — the under-count lasts one refresh interval. Alert on any increase of `pad_redis_evicted_keys_total` and size `maxmemory` with headroom (the SSE logs are the large tenant).
- **Mixed versions.** A replica of the release before keeps its in-process ledger and sees no other replica's streams: acceptable only at one replica — roll the fleet to this release before raising it.
- **Metrics.** `pad_ai_ledger_errors_total{op}` (hold, refresh, read, release, lost), `pad_ai_ledger_held`, `pad_ai_ledger_expired_total`; refusals stay in `pad_ai_budget_refusals_total{reason="unavailable"}`.
