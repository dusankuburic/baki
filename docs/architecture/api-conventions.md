# API conventions

How an HTTP endpoint takes its input, reports its errors and pages its lists. New endpoints follow it; existing ones move over when touched and keep their wire shape (error codes stay the same by construction).

## Typed endpoints

An endpoint is a function from a typed request to a typed response; `api.JSON` (JSON body) or `api.Query` (URL only, for GET/DELETE) turns it into the handler. Pipeline, in order: (1) strict body decode — an unknown field, empty body or trailing data is a 400 `BAD_REQUEST`; bodies over the router's 10 MiB limit get the usual 400; (2) `path:"name"` fields from the route, `query:"name"` from the query string — string/bool/int or slices of those, comma-separated or repeated; empty/absent = zero value; malformed = 400 naming the parameter; unknown query params ignored; give path fields `json:"-"`; a path tag not naming one of the route's parameters is a 500 before the function runs; (3) page bounds; (4) `Validate() error` (a plain error is 400 with its message; an `*apperr.Error` is written as is); (5) flow authorization; (6) the function, on the request's own context — it returns before anything is written, so the transaction commits before the first response byte (ADR 0004); (7) the response with the endpoint's `Status` option (200 default, `Status(http.StatusCreated)`, `Status(http.StatusNoContent)`); errors go through `render.Error`. `JSON`/`Query` panic at handler-build time (boot, never serve) on: a request naming a flow without `AuthorizeFlow` or the reverse; a tagged field the decoder cannot fill (embed structs by value, not pointer); `PageLimits` without an embedded `PageRequest`; a `Status` outside 2xx.

**Flow authorization.** A request implementing `FlowRef() string` names a flow; its endpoint declares `AuthorizeFlow(sec, authz, action)`: a missing flow is 404 `NOT_FOUND`, a refusal 403 `FORBIDDEN` (a scoped API token lacking the action's scope included), and the function reads the stored header the check loaded via `AuthorizedFlow(ctx)` (nil in local mode, which checks nothing). Hand-written routes remain only for streams (SSE, chat), multipart uploads, downloads, the WebSocket and raw-body webhooks, pinned per file by `TestArch_RoutesUseTheTypedAdapter` — a new file starts at zero and a file's count only goes down.

## Errors

Every error response is the envelope `render.ErrorResponse`: `{"code","message","requestId","details"}`. `code` is stable SCREAMING_SNAKE and is what clients switch on; `message` is for people and may be reworded (every 5xx masks it as `internal server error`); `requestId` is the request's `X-Request-ID`; `details` holds structured recovery fields and is never masked. An `*apperr.Error` anywhere in the chain decides status (from its kind), code and details — its cause and `fmt.Errorf` context are for the logs. Service sentinels map as ever: `ErrNotFound` 404, `ErrPermissionDenied`/`ErrScopeDenied` 403, `ErrInvalidInput` 400, `ErrConflict`/`ErrVersionConflict` 409, `ErrRLSUnavailable` 503; any other error is 500 `INTERNAL_ERROR`. Kinds (`internal/platform/apperr`, default codes): Invalid 400 `BAD_REQUEST`, Unauthenticated 401 `UNAUTHORIZED`, Forbidden 403 `FORBIDDEN`, NotFound 404 `NOT_FOUND`, Conflict 409 `CONFLICT`, Unprocessable 422 `UNPROCESSABLE`, RateLimited 429 `RATE_LIMITED`, Internal (zero) 500 `INTERNAL_ERROR`, NotImplemented 501 `NOT_IMPLEMENTED`, Unavailable 503 `SERVICE_UNAVAILABLE`. Give a specific code when a client must tell a case apart (`apperr.Conflict("FLOW_LOCKED", …)`) and list it in the `@Failure` line; a package-level `Error` may be shared (`WithDetails`/`Wrap` return copies; `errors.Is` matches by kind and code). The drain refusal is the exception (ADR 0024): 503 `SERVER_RESTARTING`, unmasked fixed message, `details.retryAfterSeconds` and a `Retry-After` header, and no log line. `render.ErrorUnlogged` writes the bytes without the ERROR log.

Specific codes: `PROVIDER_UNKNOWN` (400 on the key routes, chat create and context preview; 200 `{ok:false}` on provider tests) — the id is not in `ai.Specs()`; `USE_PROVIDER_CONFIG` (400, `/api/keys/save`) — the provider stores a document; `PROVIDER_NOT_ALLOWED` / `PROVIDER_POLICY_UNAVAILABLE` (ADR 0028) — the policy refused or could not be read; `AI_BUDGET_EXCEEDED` / `AI_BUDGET_UNAVAILABLE` — the daily budget gate; `CONVERSATION_CONFLICT` (409, `details.version`) — the conversation is no longer at `baseVersion` (ADR 0031); `REPLICA_UNREACHABLE` (503 with `Retry-After`, safe to retry) — a cross-replica stop or decision could not reach the owner, and a stop for a stream of a pre-multi-server release answers 403 `STREAM_NOT_FOUND` instead (ADR 0033); `QUERY_TOO_SHORT` (400, `details.minLength` 3) — the text has no run of 3 letters or digits as the database's trigram index counts them (vowel signs included; ASCII only under a C ctype), so the index cannot serve it (the name filters fall back to a prefix match).

## Lists

The response is `api.Page[T]`: `items` (never null), `nextCursor` (opaque, absent on the last page), `total` (only when the endpoint counts — counting is a second query). The request embeds `api.PageRequest`: `?limit=` (absent or below 1 → default 50; above the maximum 200 → the maximum; clamped, never refused; `PageLimits(default, max)` sets an endpoint's own) and `?cursor=`. Cursors are opaque keyset positions (the last item's sort key with its id as tie-breaker), valid only with the filters and sort they were issued for (malformed → 400 `BAD_REQUEST`); clients never build or parse one, and new endpoints take no offsets. `?sort=field` / `-field` on one field, JSON field names, the id always the tie-breaker, unknown fields 400. Filters: one query parameter per filter named like the JSON field; several values mean any of them (`a,b` or repeated); `q` is bounded free text; ranges are `from`/`to` as `YYYY-MM-DD`, inclusive; enumerated filter values are validated (an unknown value is a 400). The legacy paged endpoints keep `render.PagedResponse` until touched with their client; since v49 they also take cursors additively (an offset without a cursor is capped at 10 000, above which 400; `hasMore`, `nextCursor`, `totalCapped`; a cursor names its list — the user and audit cursors are refused by each other). By cursor a client reaches every row of the user list, the audit log (`X-Next-Cursor`, sent while events follow) and the library's updated-at sorts; by offset, offsets up to and including 10 000 (so 10 000 + one page by offset) — the library's name and block sorts have no cursor and end there with `hasMore: false`. A page reached by cursor that gives none is the last.

## Swagger

Annotate the wrapped function and name the types: `@Param request body <Req> true` (fields tagged `json:"-"` stay out of the schema), `@Success 200 {object} <Resp>` (a page is `api.Page[api.<Item>]`), errors as `{object} render.ErrorResponse` with the codes in the description. swag names query parameters from `json`/`form` tags, never `query` tags, so write `@Param` lines for them (a list takes `collectionFormat(csv)`). Never edit `docs/swagger.*` by hand: the OpenAPI Freshness CI job regenerates them (a changed annotation means regenerating and committing; the annotations were checked with `swag init -g main.go --parseDependencyLevel 1`).
