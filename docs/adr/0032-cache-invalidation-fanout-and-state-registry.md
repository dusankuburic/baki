# 32. Cache invalidation fan-out, access rechecks across replicas, and the per-process state registry

Date: 2026-10-13. Status: accepted, implemented (Phase 5b, wave 2). Addendum 2026-10-14.

## Context

Cache invalidation was in-process: with two replicas the second served stale settings/rules/listings for the TTL (30 s / 10 min), revocations closed other replicas' sockets only at the 2-minute periodic pass, `flow.upload-ids` minted duplicate flows, the WS ticket guard was per-process, and nothing forced new per-process state onto any list (~fifty pieces of state found).

## Decision

1. **One channel, keys only.** `internal/invalidation` implements `eventbus.Replicas` on `baki:inval` (declared `inval.fanout`, v1, on-down open; kinds `inval`, `recheck`, `hb`, `resync`). A message is the ADR 0029 envelope plus `key`, its `scope` (tenant ids only, no free text, nothing secret), the sender's `epoch` and origin: `{"v":1,"kind":"inval","key":"rules.profiles","scope":{...},"epoch":17,"o":"app-a#3f9c0a11"}`. Published after the commit only (through `txhook`, after the local Committed pass); a writer never waits on Redis. Applied by the owner's own drop (`Bus.OnRemote(key, apply)`): the same generation bump and delete, never re-published (no loops); a replica drops its own origin. Order is kept (one FIFO queue, one publishing goroutine); an empty scope drops the whole cache.
2. **Bounding a lost message.** (1) Epoch gap check: unsent messages still take their number; a skipped number or a heartbeat (every 10 s, carrying the last epoch) ahead triggers (2) resync — every replicated key dropped and every socket re-checked (`DeliverRemote(key, nil)`), on a gap, on (re)subscription, on Redis recovering and on a peer's `resync`, at most once per 5 s; a burst past the 512-slot queue collapses into one `resync`. (3) The TTLs unchanged (30 s; model listings 10 min) are all there is while Redis is down.
3. **`cache.Shared("redis-inval")`:** the shared caches are `settings.deployment`, `rules.deployment-profile`, `rules.profiles`, `providers.model-listings`, `rag.corpus-counts`, `dashboard.home`, `dashboard.analytics` (storage stays per replica; the mechanism is the invalidation). Caches needing no signal stay `ReplicaLocal`.
4. **Rechecks on the same channel:** `recheck.ws-access` and `recheck.sse-revocation` flag this replica's sockets (`Hub.Recheck*`) or end the revoked token's streams (`ApplyRemoteRevocation`); a credential recheck keeps ADR 0020's user match. A resync re-checks every socket; SSE keeps its periodic blacklist check as backstop.
5. **Direct drops** that were not events announce with `Bus.Invalidate(ctx, key, scope)` after the commit (dashboard record analysis, key saves without `CredentialChanged`, disabling lent org Azure credentials); drops an event already covers stay local.
6. **State on Redis with local fallback:** `flow.upload-id` (`baki:flow:upload-id:{user}:{digest}`, 24 h, `SET NX`; an id whose flow was deleted is replaced except within 15 s of the claim) and `ws.ticket` (`baki:ws:ticket:{jti}`, ≤2 min, `SET NX EX`) in front of the in-memory guard; the Postgres blacklist stays the authority.
7. **The state registry:** `TestArch_PerProcessStateDeclared` finds every keyed collection beside a lock and every filled-later package-level map/sync.Map and requires a `stateRegistry` entry with locality and reason (replica-local, shared-with-proof, database, request-scoped, config, desktop-only, test-only, composite); "known gap" names an unfixed cross-replica defect.
8. **Addendum — the three known gaps, closed.** `scanner.scan` (`baki:scanner:scan:{flow}`, string, 7 d): the flow's scan key and new-rules note, `MGET` per page — a replica skips a flow whose inputs match, so a sweep does not re-analyze what another replica scanned (the inbox row is already the deployment-wide alert dedup). `analysis.claim` (`baki:analysis:claim:{tenant}:{flow}`, 7 d): "fresh" (dashboard record, one trend row, the webhook) claimed with `SET ... GET` — fresh only when the old value named another run or none. `analysis.pair` (`baki:analysis:pair:{tenant}:{flow}`, hash, 24 h): fields `cur`/`prev` (run identities), `cur_at`, `cur_body`/`prev_body` (gzip of `{report, contentHash, ruleSet}`); a Lua script moves the current run to `prev` on a new record; a report that does not compress under **512 KiB** and sweep-produced runs are not stored. Keys name the stored flow by tenant (`org-<id>`/`user-<id>`) and storage id — never `StableFlowID` alone (two orgs' folders with the same file names would share). The pair never moves back (older `cur_at` leaves it); decoded reports are kept in the declared cache `analysis.shared-runs` (32 MiB). All three run only with `PAD_MAX_REPLICAS > 1`, fail open (every error falls back to the replica's own state, off Redis for 30 s), and cost ~200 B per stored flow (7 d), ~100 B per analyzed flow (7 d), ≤2 × 512 KiB per interactively analyzed flow (24 h) of Redis memory.

## Consequences

A committed write reaches a peer in a message's latency instead of a TTL; a rolled-back write publishes nothing. Metrics: `pad_inval_published_total{kind}`, `pad_inval_received_total{kind}`, `pad_inval_dropped_total{reason}`, `pad_inval_ignored_total{reason}`, `pad_inval_gap_total`, `pad_inval_resync_total{reason}` — a sustained gap rate means the channel loses messages. A new per-process map fails `TestArch_PerProcessStateDeclared` until its author decides what a second replica sees. The channel is a trust boundary: whoever can publish can drop caches, force socket re-checks and end a token's streams — it cannot read data, grant access or change a value. Rollback is additive (older replicas keep the TTL windows; keys expire; no schema change); the first 5b deploy stays at one replica. Open: `dashboard.*` drops only the owner's and the org's views (other collaborators wait out the TTL).
