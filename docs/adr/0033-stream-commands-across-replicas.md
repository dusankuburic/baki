# 33. Stream commands across replicas

Date: 2026-10-13. Status: accepted, implemented (Phase 5b, wave 2).

## Context

A chat stream lives in the memory of the replica that started it, but stop (`/api/chat/cancel`), an approval decision (`/api/chat/fix-decision`) and a reload (`/api/chat/get`) arrive on any replica: stop did nothing and answered `ok` (the stream kept spending), a decision answered 404 (the card died, the stream waited out its 60 s timeout), a reload reported no stream so the answer was lost.

## Decision

1. **The snapshot names its owner:** `resumeSnapshot` gains `replica` (instance id) and the envelope (`v:1, kind:"chat.resume"`), stamped by `Save`. A snapshot without `replica` (previous release) cannot be commanded: a stop answers the 403 `STREAM_NOT_FOUND` that release gave (the client takes it as gone, no retry loop); a decision stays 404.
2. **A command bus, `redisx.CommandBus`:** channels `baki:chat:cmd:<instance>` and `baki:chat:reply:<instance>`, subscribed from `StartCommands` to the end of `Shutdown`. `Call(target, requestID, payload, wait)` waits at most 2 s, failing fast with `ErrNoReceiver` when `PUBLISH` reports no subscriber, `ErrNotReady` when the reply subscription is down, `ErrNoReply` after the wait. Handlers run bounded at 64 in flight per replica; payloads over 16 KiB are ignored.
3. **The command `chat.cmd` v1:** `{op, streamId, scope, requestId, replyTo}` plus `proposalId, approved, excluded, tokenScopes` for a decision; `op` is `cancel` or `decide`; reply status `ok | gone | no_pending | forbidden | scope_denied | unsupported`. **The owner decides again:** it finds the stream, compares `ctl.ownerID` to `scope` and calls the same `ResolveApproval` the local path calls (scope check rebuilt from `tokenScopes`); the asking replica's checks are an early refusal, not the authority.
4. **Approvals.** `requestApproval` writes `baki:chat:approval:<proposalID>` = `{stream, replica, scope}` (TTL: the wait + 10 s) before the card is shown; ids over 128 bytes are refused before use in a key. A decision that finds no pending on this replica reads the key (missing/another stream's → 404; wrong scope → refused, nothing sent), then takes `SET NX baki:chat:decision:<proposalID>` (TTL 60 s): **the first decision from any replica wins the claim; a loser waits for the winner's outcome and reports it** (claim states `sending`/`done`/`lost`; a delivery known not to have happened releases the claim, one that may have marks it `lost` with the decision — a retry of the same decision answers `ok` once applied, the opposite answers `no_pending`; nothing settles → 503). The owner's in-channel buffer stays the authoritative first-wins; a local decision touches no Redis. A failed write of the pending key is logged only.
5. **Reload:** `baki:chat:active:<digest of scope, flow, conversation>` = `{stream, replica}` (TTL as the snapshot), written the first tick after the question is stored, cleared when the answer settles; `ReadConversation` consults it, checks `snapshot.Owner == scope`, and drops a stream whose finished answer the stored history already ends with.
6. **Redis down:** an unreadable snapshot, an owner that does not answer and a failed publish are **503 `REPLICA_UNREACHABLE`** with `Retry-After: 2` and `details.retryAfterSeconds` — never a false `ok`. A command is safe to send twice (stop idempotent, decision guarded by the claim). A stream on the receiving replica is untouched by an outage.
7. **Commands are signed.** When the replicas share a secret, every command and reply travels in a signed frame: key = HKDF-SHA256 of `PAD_ENCRYPTION_KEY` (else `PAD_AUTH_SECRET`; a per-process secret never qualifies) with a purpose label; the MAC covers direction, receiver, timestamp, nonce and body; accepted only within 30 s of the receiver's clock with an unseen nonce (a bounded cache that refuses rather than forgets). Rejected frames are counted in `pad_redis_bus_rejected_total{reason}`. Without a shared secret the bus runs unsigned and the boot says so (private network, password, TLS are then the only defence). A rolling key change leaves commands unanswered (503, retry) for the overlap; clocks must agree within 30 s.
8. **Close-out — caps and a dead owner (only with `PAD_MAX_REPLICAS > 1`):** the per-caller stream cap holds across replicas via a `SlotCap` sorted set `baki:chat:streams:{scope}` (3 per caller, lease 30 s rewritten every 10 s, judged with `TIME`, a dead replica stops counting within 30 s, refusal 429 `CHAT_CAPACITY_REACHED`, fail open on a Redis error); `clientStreamId` is claimed with `SET NX baki:chat:stream-id:{stream}` (TTL: the stream's life, then 2 minutes; a refused start gives the claim back). Each replica keeps `baki:replica:live:{origin}` (`replica.live`, written every 5 s, TTL 15 s, deleted on clean stop). A relayed stop/decision with no answer and `live: true` reads the key: absent → the stream died with its replica (stop answers `ok`, the stale snapshot is compare-deleted so resume says `STREAM_NOT_FOUND`; a decision answers 404 with the claim released); present or unreadable → 503. **A missing key must mean a dead replica:** the owner fences itself (no successful liveness write for 10 s → it stops every stream it published with `STREAM_INTERRUPTED`, repeated while it cannot write, and checked before a write), writes its key at once on resubscribe/recovery, and the origin believes a missing key only on a steady view (own subscriptions unbroken, Redis not degraded, ≥15 s) — otherwise 503.

## Consequences

Stop, decisions and reload work from any replica; with one replica or no Redis the paths are the ones that existed. Cost: one GET per conversation read (400 ms bound), two GETs and a publish per relayed stop, three round trips and a claim per relayed decision. Metrics: `pad_chat_commands_total{op,side,outcome}` and `pad_chat_command_seconds{op,answered}`. Instance ids need not be unique (the boot-suffix origin, ADR 0030). Rollback: pub/sub channels vanish with the binary; claim/approval/active keys expire within minutes; no migration. Still open: a resume (not a stop) of a dead replica's stream serves the stale snapshot until it expires or a stop removes it.
