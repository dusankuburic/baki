# 1. Record architecture decisions

Date: 2026-10-06. Status: accepted.

## Context

Design decisions lived in code comments and commit messages, which explained what was done but rarely the rejected alternatives or the accepted consequences.

## Decision

Record each decision with lasting consequences as a short ADR in `docs/adr/`, numbered in order: context, decision, consequences. An ADR is never edited after acceptance except to mark it superseded by a later one.

## Consequences

Reviewers can point at the ADR instead of reconstructing the reasoning. ADRs are kept for decisions that constrain future work, not for routine changes.
