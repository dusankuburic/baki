# 19. Organisations mint their own CI credentials; the deployment secret is deprecated

Date: 2026-10-10. Status: accepted.

## Context

`POST /api/integrations/ci` authenticated one deployment-wide HMAC key (`PAD_CI_WEBHOOK_SECRET`) and loaded the flow on the pool outside row-level security, so whoever held the secret could analyse any tenant's flow and record runs on its dashboard. Rotating the secret broke every runner at once; nothing could be revoked per organisation.

## Decision

1. Org admins mint credentials in `org_ci_credentials` (0038, expand): key id, organisation, name, secret, hint, minter, optional expiry (1-365 days), last use; org-member RLS; cascade on org delete; at most 10 unexpired per org. Format `baki_ci_<keyId>_<secret>` (16-char base32 key id, 32 random bytes base64url); the HMAC key is the whole string, signature `"sha256=" + hex(HMAC-SHA256(key, ts + "." + body))` (`internal/platform/hmacsig`), so an old bakicli signs correctly.
2. The secret is sealed with field encryption (ADR 0005); the store refuses to write without the key (503 `CI_CREDENTIALS_UNAVAILABLE`). Only the create answer carries the credential; an `Idempotency-Key` retry replays it.
3. Identification, in order: `X-Baki-Key-Id`; else the deployment secret; else (old clients, no key id) the unexpired credentials of the org owning the flow the body names. Every pre-auth failure is the same 401 (except a missing `X-Baki-Timestamp`, which says so). `pad_ci_webhook_auth_total{method="key_id|global|flow_org|token"}` counts.
4. Scoped resolution: a credential reaches only its organisation's flows (`LoadFlowHeaderInOrg` puts the org in the SQL predicate); a flow outside answers the same 404 as an unknown one, after authentication. The run carries `auth.ActorIntegration` (refused everywhere by authorization); one `ci.webhook_run` audit row per call. The route is `Needs(ServerStore)`, on the `analysis` rate-limit bucket (`PAD_RATE_LIMIT_EXPENSIVE_*`, 429 with `Retry-After`), runs `AnalyzeFlowFresh`, records the dashboard only for a fresh report; unknown `format` is 400 `UNKNOWN_FORMAT` with `details.formats` (`summary`, `report`, `sarif`). Last use is written off the response path, at most once per 5 minutes.
5. Admin API (org-admin, `Needs(ServerStore, Accounts)`, `DenyTokens`): `GET/POST /api/orgs/{id}/ci-credentials` and `DELETE .../{credId}`. The create is not `Idempotent` (a replay would hand the one-time credential out again); a retried mint mints another. Rotate by minting, switching, revoking. Lifecycle: no export; erasure clears `created_by`; org delete cascades; the sweep removes credentials 30 days after expiry.
6. The deployment secret per profile: desktop 503; local+db without accounts — the secret is the only key, not deprecated; with accounts — org credentials are primary, the secret still works with a boot WARN, `Deprecation: true` and a `Link` on every answer. `PAD_CI_WEBHOOK_ALLOW_NO_TIMESTAMP` (exactly `"1"`) applies to the deployment secret only, deprecated.
7. **A delivery id against replays.** The body carries `deliveryId` (covered by the signature; bakicli sends 128 random bits per invocation, kept across 429-rate-limiter retries). The server validates it (16-128 chars of `A-Za-z0-9-_`), then inserts `(caller, delivery_id)` into `ci_webhook_deliveries` (0039, expand) with `ON CONFLICT DO NOTHING`, after authentication and before the flow is resolved: a pair already present is 409 `CI_REPLAYED` and nothing runs; of concurrent calls with one id exactly one wins. `caller` is `credential:<key id>`, `secret` or `token:<id>`. A call without an id is accepted (`pad_ci_webhook_deliveries_total{delivery="new|replayed|missing"}`). Records are kept an hour; each insert removes its caller's older records; the table's RLS admits the pool only.
8. **Personal CI: the `ci` token scope.** API tokens get a fifth scope `ci`, granting the webhook only (refused 403 everywhere else). The webhook takes `Authorization: Bearer <API token>` instead of a signature (bearer header decides alone; a token without `ci` gets the 401). The token reaches flows its user can read via action `CIRun` (viewer access, scope `ci`); an org's flow also needs membership of that organisation (any role) — a non-member collaborator is refused (`RuleProfile.Narrowed` would otherwise analyse without the org's rules). `bakicli report -token`/`$PAD_CI_TOKEN` excludes `-secret`; bakicli refuses a token over plain HTTP to non-loopback. A bearer token is not sender-constrained: a captured call can be resent with a new delivery id (defence: HTTPS, expiry, revocation, the narrow scope).

## Consequences

A leaked credential reaches one organisation and can be revoked. Rollback keeps the tables (expand); runners on org credentials get 401 until the release returns. A captured signed call runs once (a repeat within the hour is 409). A delivery id is claimed before the analysis: a call that then fails has used its id. Existing tokens reach nothing new; a user mints a `ci` token to use the webhook.
