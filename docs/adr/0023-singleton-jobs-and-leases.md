# 23. Singleton jobs and leases

Date: 2026-10-10. Status: accepted; adopted by every advisory-lock user except the blocking schema-migration lock.

## Context

Must-run-on-one-replica background work took a session advisory lock with three failure modes: fail open (the scanner and retention purge swept without the lock on a lock error, so every replica swept at once), no lease check (a dead lock connection let two replicas run side by side; `pg_advisory_unlock` returning `false` was ignored, leaking the lock under a pooler), and panics ending a ticker loop for good. Admin-triggered runs under `context.Background()` were never cancelled at shutdown.

## Decision

1. **Leases** (`internal/platform/lock`): `Lease{Lost() <-chan struct{}; Release()}` and `Leaser{TryLease(ctx, key)}`. The Postgres lease takes the session advisory lock on a pinned connection and heartbeats it every 15 s (5 s timeout) via `pg_locks`; a session that does not answer or no longer holds the lock loses the lease (`Lost` closes, session discarded, `pad_advisory_lease_lost_total`). An unlock answering `false` is a lost lease: counted (`pad_advisory_unlock_not_held_total`), logged, session discarded.
2. **`lifecycle.Singleton`** runs `Job{Spec, Every, RunAtStart, Timeout, RetryOnLockError, OverdueAfter, Run}`. Lock error → skipped, fail closed (`pad_job_skipped_total{reason="lock_error"}`, retried after `RetryOnLockError`); held elsewhere → skipped (`reason="held"`); no leaser (desktop) → the process runs the job alone. The run's context ends on `Timeout`, on `Stop` and when the lease is lost (`ErrLeaseLost`); panics are recovered per run and reported (`errreport` location `job.<name>`). `RunNow(ctx)` is the operator's "run it now" (lock under the caller's context, run in background); every job joins the process-wide group and `lifecycle.DrainAll` cancels and waits at shutdown. Metrics: `pad_job_runs_total{job,outcome=ok|failed|lease_lost|panic}`, `pad_job_duration_seconds{job}`.
3. **Persisted state.** Migration 0041 (expand): `job_runs(name PK, last_started_at, last_success_at, last_error_at, last_error, holder_instance)`, one row per job, written by the running replica (error text cut at 1 KiB); no RLS (listed, not purged). Store: `storage/interfaces.JobRunStore`, a role of `StorageBackend` held by contract scenarios; the Singleton takes the narrower `lifecycle.JobState`. Writes are best effort (5 s deadline, logged, never fail the job).
4. **Overdue.** After every attempt without success the job reads the last success on any replica and sets `pad_job_overdue{job}` = 1 with WARN `job overdue` (then hourly) when it is older than `OverdueAfter` (default 2× `Every`); counted from the later of that success and process start. `pad_job_last_success_timestamp_seconds{job}` follows the persisted value. A leaked lock shows as overdue, not endless "held".
5. **Fixed log messages** (`lifecycle.LogJob*`, never reworded): WARN `job overdue`, `job lease lost`, `job skipped: lock unavailable`, `advisory unlock reported not held; discarding connection`, `advisory lease lost; discarding its session`.
6. **Registry and keys.** `lifecycle.DeclareJob(JobDecl{Name, LegacyKey, Schedule})` at package level. A pre-registry job keeps its legacy key (a new key during a rolling deploy would let old and new revisions run the job side by side); a new job derives its key, FNV-1a-64 of `"baki:job:"+name`. Malformed/duplicate declarations panic at init. `internal/lifecycle/testdata/jobs.golden` lists every job; `TestJobKeys_Unique` reads every lock-key constant from source.
7. **Adopted everywhere:** scanner (`ScanNow` = `RunNow`: 409 `SCAN_ALREADY_RUNNING`, 503 `SCAN_UNAVAILABLE` on lock error), retention purge, field-encryption backfill, secret re-seal, audit org backfill, legacy migration (`RunNow`, cancelled at shutdown), token-blacklist cleanup, knowledge HNSW build. Keys: `bakiscan`, `bakiretn`, `bakifenc`, `bakikrot`, `bakiaudo`, `bakimigr`, `bakiblck`, `bakihnsw`, plus derived `schema_upkeep`. All state in `job_runs`; the schema-migration lock stays blocking by design.

## Consequences

A database blip skips a sweep instead of letting every replica sweep; a lost lock ends the run; a panic costs one run; admin runs end at shutdown. Behind a transaction-mode pooler (unsupported) every lease is lost loudly at its first heartbeat. Each running job pins one pooled connection (the HNSW build and `schema_upkeep` two, the upkeep after every boot of a database deployment; a pool under 3 skips both) and sends one small statement per 15 s. Rollback: 0041 only adds a table the previous release never reads; keys unchanged, so revisions exclude each other as before.
